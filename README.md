# «Легче» — экосистема доступной мобильности

Адаптивный лендинг на Next.js (App Router), React, TypeScript и Tailwind CSS. Тексты основаны на обеих страницах предоставленного ТЗ. Оригинальный цветной знак `logo/legche-mark.svg` используется без перерисовки; рядом размещено название бренда. Знак также используется как favicon. Никаких внешних шрифтов, аналитики или рекламных трекеров нет.

## Запуск

Нужен Node.js 22 или новее, npm и доступ к npm registry для установки.

```sh
npm ci
cp .env.example .env.local
npm run dev
```

В PowerShell вместо `cp` можно использовать `Copy-Item .env.example .env.local`. Откройте `http://127.0.0.1:3000`. Для другого порта измените `SITE_ORIGIN`.

```sh
npm run typecheck
npm test
npm run build
npm start
```

При сборке секреты не нужны. Без настройки CRM и реквизитов оператора форма возвращает ошибку 503 с честным сообщением, что заявка не отправлена. Данные не складываются в очередь и не сохраняются на сайте.

## Как подключить Bitrix24

**Редактировать код сайта, форму, кнопки или сообщения при подключении не нужно.** Заполните серверные переменные ниже и перезапустите процесс сайта. Обработчик читает настройки на сервере во время запроса. Сообщение «Ваша заявка не отправлена» — условный ответ при отсутствии настройки; после подтверждения создания лида автоматически показывается сообщение об успехе. Пересборка для изменения этих серверных переменных не требуется.

После production-сборки можно выполнить `npm run test:api`: проверка запускает отдельный временный сервер на порту 3107 и подтверждает переход от 503 без webhook к 200 с webhook исключительно изменением окружения. Ответ Bitrix24 имитируется локально, внешних запросов и реальных лидов нет. Проверяется и ошибка CRM (502). По завершении временный сервер выключается. Проверочный mock никогда не используется обычными `npm run dev` / `npm start`.

### 1. Подготовить портал

Проверьте, что CRM вашего портала поддерживает лиды и пользователь интеграции имеет право их создавать. Входящий вебхук должен иметь доступ к CRM (`crm`). Если портал работает только со сделками, сначала настройте режим с лидами или адаптируйте серверный модуль под согласованную сущность.

Создайте входящий вебхук в инструментах разработчика Bitrix24. Скопируйте базовый URL вида `https://ВАШ-ПОРТАЛ/rest/ID-ПОЛЬЗОВАТЕЛЯ/СЕКРЕТ/`. Это форма адреса, а не рабочие реквизиты. Не дописывайте метод к переменной: модуль сам добавляет `crm.lead.add.json`.

### 2. Заполнить серверное окружение

В `.env.local` для локального запуска, а при публикации — в секретах сервера:

| Переменная | Назначение |
| --- | --- |
| `BITRIX24_WEBHOOK_URL` | Базовый HTTPS URL реального входящего вебхука, обязательно |
| `BITRIX24_ASSIGNED_BY_ID` | Числовой ID ответственного сотрудника, необязательно |
| `BITRIX24_SOURCE_ID` | Источник лида; по умолчанию `WEB`. Для своего источника укажите его ID из CRM |
| `BITRIX24_TIMEOUT_MS` | Тайм-аут запроса; по умолчанию 10000 мс, допустимо 1000–30000 |
| `SITE_ORIGIN` | Точный origin сайта, например `https://ваш-домен.ru`, без пути и завершающего слеша |
| `TRUST_PROXY` | `true` только если доверенный прокси перезаписывает `X-Forwarded-For` |
| `DATA_OPERATOR_NAME` | Реальное полное наименование оператора данных |
| `DATA_OPERATOR_ADDRESS` | Адрес оператора |
| `DATA_OPERATOR_EMAIL` | Действующий email для обращений и отзыва согласия |

Ни одна переменная с секретом не должна иметь префикс `NEXT_PUBLIC_`. Не коммитьте `.env.local` и не пересылайте вебхук в публичном чате. Доступ к вебхуку равнозначен доступу к разрешённым CRM-операциям. При утечке отзовите его и создайте новый.

До включения формы заказчику нужно проверить текст политики и согласия, условия хранения в своей CRM и реквизиты оператора. Реквизиты не выдуманы: без их заполнения сервер не отправляет заявки. Политика на `/privacy` динамическая: новые серверные настройки отражаются после перезапуска, без подстановки секретов в клиентский код.

### 3. Перезапустить и проверить

1. Перезапустите процесс Next.js после изменения переменных. На хостинге выполните повторный запуск/развёртывание по правилам площадки.
2. Откройте сайт именно по origin, указанному в `SITE_ORIGIN`.
3. Заполните форму своими тестовыми контактами с согласия их владельца; не используйте чужие данные. Подождите как минимум две секунды после открытия страницы.
4. После отправки дождитесь подтверждения. Успех появляется только при положительном числовом ID лида в ответе Bitrix24.
5. Откройте CRM → Лиды. Найдите «Легче — заявка на бесплатный подбор» и проверьте имя, телефон, комментарий, источник и ответственного. В комментарии также записываются время и версия согласия.
6. Удалите свою тестовую заявку из CRM, если она больше не нужна.

Полезно проверить отдельно: пустое имя, неполный телефон, отсутствие согласия, незаполненный вебхук и ошибку CRM. Ошибки остаются в форме, введённые данные сохраняются до успешной отправки. Не отправляйте тестовые данные в сторонние сервисы.

Официальная документация метода: https://apidocs.bitrix24.ru/api-reference/crm/leads/crm-lead-add.html. Метод выбран согласно задаче, поддерживается Bitrix24, но больше не развивается; дальнейшую миграцию на `crm.item.add` можно выполнить внутри `src/lib/bitrix24.ts`, не меняя форму и `/api/lead`.

## Какие данные создаются в лиде

`TITLE`, `NAME`, `PHONE` (MOBILE), `COMMENTS`, `SOURCE_ID` и, если задан, `ASSIGNED_BY_ID`. Текст комментария очищается от угловых скобок. Подтверждение об успехе выдаётся только после ответа CRM; сырые ответы, ID лида и внутренние ошибки пользователю не раскрываются.

## Защита и ошибки

- Проверка origin, JSON content type, лимит тела 16 КБ, серверная валидация имени/телефона/согласия.
- Невидимое для посетителя поле-ловушка и минимальное время заполнения две секунды. Это базовые меры, не полноценная CAPTCHA.
- До 5 запросов за 10 минут на ключ. При `TRUST_PROXY=false` применяется общий лимит процесса: безопасный режим для локальной проверки, но его обязательно нужно адаптировать перед нагрузкой.
- За доверенным прокси ключ — SHA-256 IP, только в памяти, не в журнале. Устаревшие ключи очищаются при запросах. Нельзя доверять заголовку от произвольного клиента.
- Для публичного сайта настройте лимит на reverse proxy/WAF. При нескольких процессах/серверless инстансах нужен общий лимитер: локальная память не обеспечивает единый лимит и очищается после перезапуска. Не включайте доверие к IP-заголовку, если прокси его не перезаписывает.
- `400` — некорректный запрос/ловушка/слишком быстрая отправка; `403` — чужой origin или отсутствующая настройка origin в production; `413` — большое тело; `415` — не JSON; `422` — поля; `429` — лимит; `503` — настройка не завершена; `502` — сбой CRM/тайм-аут.
- Автоматических повторов отправки в CRM нет: при сетевом тайм-ауте CRM могла уже создать лид. Проверьте CRM до ручной повторной отправки; пользователь видит сообщение о невозможности подтвердить результат.
- Приложение не логирует контакты, комментарии, тело запросов или webhook. Проверьте также настройки логирования на вашем хостинге и прокси.

## Публикация

Проект намеренно использует настоящий Next.js, как указано в задании. Для API нужен Node.js-хостинг с поддержкой Next.js; статический экспорт и обычная папка HTML не подойдут. Локальная реализация не означает публикацию в интернете. Среда Sites использует другой серверный runtime; исходный проект не заменён на другой фреймворк ради размещения.

Обычный запуск: `npm ci`, `npm run build`, `npm start`. По умолчанию сервер доступен на loopback для reverse proxy. Для контейнера запускайте `next start --hostname 0.0.0.0` с нужным `PORT`. Нужны HTTPS, корректный `SITE_ORIGIN`, серверные секреты и защищённый прокси. Используйте актуальные исправления безопасности зависимостей.

## Что предоставить для запуска приёма заявок

1. Реальный серверный URL входящего webhook Bitrix24 с правом создания лидов.
2. При необходимости ID ответственного и источника, а также сведения об обязательных пользовательских полях CRM.
3. Публичный домен сайта и выбранный Node.js-хостинг.
4. Реквизиты оператора, контакт для обращений и утверждённые тексты политики/согласия.

Все остальные части лендинга работают без подключения CRM.
